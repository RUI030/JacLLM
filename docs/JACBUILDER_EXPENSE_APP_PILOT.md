# JacLLM expense app pilot

Date: 2026-10-30. This is a fresh, isolated app-building test of the actual local JacLLM Student through the existing JacBuilder MainAgent/byLLM loop. The task required an expense name, positive amount, Food/Transport/Other category, total, category filter, delete, and localStorage persistence. The exact task, runner, executed entry files, workspace copies, and raw JSONL trajectories remain under `output/jacbuilder_collection/expense-app-pilot-v1/`. No production harness, model, dataset, or shared server configuration was changed.

The second run's shadow Supervisor returned `CONTINUE` in all 12 iterations. Its current deterministic rules treat each successful `read_file` as progress, so they miss identical repeated observations with unchanged workspace state. This is direct evidence for a post-execution stagnation rule using repeated `(tool, arguments, observation, source digest)` plus a minimum streak. The first run instead demonstrates output-token exhaustion after unsuccessful compiler-feedback repair. Neither a failed tool call nor a single repeated read would be sufficient to escalate.

The `Binary file` observation has a concrete tool-side cause: `jac_coder/tool/read/filesystem.impl.jac:_binary_notice` treats every known MIME outside `text/*` and `application/json` as binary. In the local runtime, `mimetypes.guess_type("jac.toml")` returns `application/toml`, so `read_file` never reaches `Path.read_text()`. This source-backed diagnosis is specific to the read tool; the Student's repeated decision to retry the same observation is separate. The same rule may affect other textual `application/*` formats, but those were not exercised in this pilot.

## Evidence and safety boundary

The first run's `independent-checks.json` contains exact commands and compiler output. The second run's `verification/` directory contains compiler/startup results, `browser-snapshot.txt`, `expense-ui-checks.json`, `app.png`, and `server-stopped.json` with `reaped=true`. The second run's browser snapshot contains the scaffold splash text and no expense input or Add expense button. The first run's terminal journal has no active or pending tool bodies, but the existing recovery runner rejects any capability refusal; therefore this experiment did not bypass that fail-closed handoff rule. The second run was also left as a Student-only diagnostic. No Teacher was invoked and no SFT rows were exported.

## Remaining validation

The Supervisor negative controls now cover changed-file and changed-page rereads. The first run's accounted, nonexecuted `missing_local_read` refusal still needs a separate handoff-policy review; the ownership rule was not relaxed. A bounded Teacher recovery, independent compiler/browser acceptance, and explicit Student continuation remain to be tested for this expense task. Retain Student failures as context, not positive targets.

## Fix and fresh rerun

After the pilot, JacBuilder's `read_file` now allows `application/toml` and `application/x-toml` as text. The experimental shadow Supervisor records three identical successful reads with the same action, observation and file digest as `CONTINUE`, `OBSERVE`, `ESCALATE`; a changed digest or different page resets the streak. A separate small fix records anti-pattern guard `BLOCKED:` results as failed tool outcomes. These changes do not enable automatic intervention or relax the ownership gate.

Each new regression test was run before its fix and failed for the observed reason, then passed after the fix. Complete affected files passed: 23/23 read boundary tests and 27/27 intervention slice tests under pinned Jac 0.34.28. Parse-only validation passed all four touched Jac files. Full `jac check` still reports existing type-check noise across these files; its archived output is `static-check.log`. An explicit cast in the new test's JSON extraction removed its one new static diagnostic, returning that file to its prior 14 errors; the final focused runtime test passed. The repository's `scripts/check_tests_wired.sh` still fails on archived test files inside `docs/experiments/`, not on the newly added tests.

A fresh run, `agent-app-pilot-3vgr1r98`, copied the fixed source and used the same expense task with the 16,384-token cap. The prior TOML loop did not recur. Student wrote a frontend but ended with JSX syntax errors; independent `jac check main.jac` and `jac check frontend.cl.jac` both exited 1. The raw trajectory and exact compiler output are retained in that run's `episodes/` and `independent-checks.json`. One rejected write had returned `BLOCKED:` while its old journal status was `ok`; that observation motivated the third regression fix. This run is a failed app build, not an SFT target or a Teacher recovery. A further live app success remains unverified.

The rejected write also exposes a separate experiment-tool mismatch: the anti-pattern guard directs the Student to call `load_jac_skill`, while this app pilot exposes only read/write/edit/finish and the experimental gate audits skill loading only for Teacher. The Student did receive the initial skill bodies in trusted instructions, but could not obey that specific tool instruction. This was observed and left unchanged; extending the Student tool set requires its own safety and compatibility test.
