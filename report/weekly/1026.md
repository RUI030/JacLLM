## 0. Units

| term | definition used here | where it comes from |
|---|---|---|
| **turn** | one main-agent `respond` invocation: one user message to final answer. One `.json.gz` trace file = one turn | `dataset/raw/prod/README.txt`; `clean.py:build` |
| **session** | traces sharing `session_id` | trace top-level field |
| **project** | unique `prj_*` directory name (= `project_id`) | path under `dataset/raw/prod/<date>/` |
| **planner chain** | one `PlannerAgent.do_work` run inside a turn (a sub-agent with its own context) | `clean.py:planner_chains` |
| **sample / row** | one line of `train.jsonl` / `valid.jsonl`: one main turn or one planner chain | `clean.py:write` |
| **model call** | one `/v1/chat/completions` request = one proxy record | `calls.jsonl` |
| **tool call** | one entry of `tool_calls` in a model response; a model call can carry 0–4 | proxy responses / agent event logs |
| **supervised token** | token with label ≠ −100 under `sft_img.Collator`: the tokens of an assistant block with `weight == 1`, from after the generation prompt `<think>\n` through `<|im_end|>\n` (reasoning, `</think>`, text, tool-call JSON) | `script/train/sft_img.py:106–160`, label assignment at 156 |
| **call index (jac_coder)** | 0-based position of the model call in the run's `calls.jsonl` (0–100). A tool call and its error are attributed to the call that **issued** it (its result is seen by the next call) | — |
| **event index (opencode/pi)** | 0-based position of the tool call in the agent's own `agent.jsonl` (`tool_use` / `tool_execution_start` events) | — |

## 8. Discord update (claims limited to the evidence above)

> Quick update from me 👋
>
> The JacHammer prod data is in: 226 agent turns, 84 sessions, 83 projects (teacher was mostly GLM-5.3-Flash). I trained a first SFT on it on top of v1.35.
>
> Data prep: whole sessions don't fit (only 7/84 fit in 64k), and 64k is the longest I've gotten training to run on our 48GB card (80k OOM'd in a memory probe, text-only and on random tokens, so not the exact training setup). So each turn becomes one sample: system prompt + as much recent history as fits (oldest messages dropped first) + the whole current turn. That gives 218 samples, ~9.4M tokens, ~625k supervised tokens in train.

Then I ran it as an actual agent (jac_coder, opencode, pi) on a todo-app task. Tool calls are well-formed and jac_coder fixed its first two build/runtime errors (opencode spent ~40 tool calls on an error page instead), but every run ends up repeating the same one or two actions for most of the time budget (e.g. 25 refused reads of the same file with the offset +1 each time, 364 identical failed `fill`s in a row, two snapshot greps alternated 399× each). pi's app actually worked about a minute in (items added and shown); it then kept grepping the page for an error message until timeout. In jac_coder, after the harness compacted its context, it also cited code that was never written and used a wrong project path twice (one run, so just an observation). I can't say yet whether the SFT helped or hurt with paths, since I haven't run v1.35 on the same task. That baseline is next.
